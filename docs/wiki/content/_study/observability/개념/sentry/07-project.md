# Project 와 화면

GitHub 의 조직/저장소와 같은 계층이다. **알아야 하는 단위는 Project** — Organization 은 결제·멤버 관리 단위라 개발자가 만질 일이 없다.

```
Organization          결제 · 멤버
└── Project           ← DSN · 쿼터 · 알림 규칙 · Inbound Filter
    └── 이슈들
```

프로젝트를 서비스마다 나눌지 하나로 합칠지가 첫 결정이다. 합치면 쿼터·알림 규칙을 한 곳에서 보지만 이슈가 섞이고, 나누면 반대가 된다. 합칠 경우 서비스 구분은 태그가 담당한다.

**합칠 때의 조용한 위험은 쿼터 공유다** — 한 서비스가 폭주해 쿼터를 다 쓰면 나머지 서비스의 이벤트도 같이 버려진다.

주로 보는 화면 둘:

- **Issues 목록** — 이슈별 한 줄씩: 제목, 이벤트 수, 영향받은 사용자 수, 발생 추이 그래프, last seen. 상단에 [검색창](./05-alert#_3-검색·쿼리-문법-—-알림-조건과-같은-축) 과 environment 선택
- **이슈 상세** — 이 이슈에 뭉친 이벤트들을 파고드는 곳
  - stack trace (소스맵이 있으면 원본 코드 위치로)
  - breadcrumbs, 태그·extra·context
  - **태그 분포** — 이 이슈의 이벤트들이 어떤 태그 값으로 구성돼 있는지 통계. 이슈가 뭉쳐 있을 때 "이 안에 뭐가 섞여 있나"를 여기서 확인한다
  - Replay 링크, 이벤트 하나씩 넘겨보기
